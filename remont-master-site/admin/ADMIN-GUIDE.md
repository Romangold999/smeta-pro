# РемонтМастер — руководство администратора

## Адреса

- Админка основного сайта: https://romangold999.github.io/smeta-pro/remont-master/admin/

- Публикация: GitHub Pages workflow на ветке `remont-master-pages`

## Авторизация

GitHub Pages — статический хостинг: он не может проверить пароль на сервере. Поэтому отдельный PIN/пароль сам по себе не защищает запись в репозиторий. Админка использует Fine-grained Personal Access Token GitHub с доступом только к репозиторию `Romangold999/smeta-pro`.

Создать токен: https://github.com/settings/personal-access-tokens/new

Минимальные права:
- Repository access: Only select repositories → `smeta-pro`.
- Contents: Read and write — чтение/изменение JSON и загрузка изображений.
- Actions: Read and write — запуск Pages-публикации из админки и чтение статистики артефактов/кэша.

Токен вводится в форме входа, хранится только в памяти текущей вкладки, не записывается в localStorage, не добавляется в Git и очищается при выходе/закрытии страницы. Не пересылай его и не вставляй в публичные файлы. Установи срок действия токена и отзывай его в GitHub, если доступ больше не нужен.

## Что умеет админка

- Профиль: имя, специализация, регион, телефон, ссылки Telegram, WhatsApp и MAX, фото профиля.
- Главная: надзаголовок, заголовок, описание и текст кнопки.
- Каталог работ: все 317 исходных позиций доступны по своим 15 категориям. У каждой записи редактируются все фактические изменяемые поля модели: название, категория, единица измерения и цена. Стабильный ID показан отдельно и защищён от случайного изменения. Доступны добавление, удаление, перенос между категориями, создание/переименование/удаление пустых категорий.
- Услуги: редактирование названий, кратких и полных описаний, иконок, переходов и порядка карточек.
- Архитектурный бетон: редактирование шести исходных карточек изделий, добавление/удаление, изображения и порядок. Заголовок и описание раздела редактируются в профиле.\n- «Сделай сам»: добавление/редактирование/удаление фотографий и Rutube-видео, описание и порядок материалов.\n- Портфолио: редактирование названий ровно четырёх категорий; изображения и ссылки Rutube; редактирование подписи/описания/категории; изменение порядка и удаление.\n- Публикации: статьи, новости, объявления; черновик/публикация; закрепление; обложка.
- Статистика: размер репозитория, текущие файлы сайта, ресурсы, данные, размер Pages-сборки, остаток Pages, рост дерева за 7/30 дней, доступный трафик, Actions artifacts и cache.

После нажатия общей кнопки админка записывает все подготовленные изменения одним commit в `main`, затем после коммита в `main` автоматически запускается GitHub Pages workflow, который собирает сайт из той же ветки `main`. После завершения публикации изменения появляются на основном сайте. В админке нет встроенного просмотра сайта: результат владелец проверяет отдельно, открывая основной сайт.

## Cloudflare

Публичная Git-only версия не подключает Cloudflare Worker: в `index.html` и `site-data.js` нет его URL и вызовов. Старый Worker и его R2-объекты могут по-прежнему существовать в аккаунте Cloudflare; удалить их из аккаунта можно только через авторизованную панель Cloudflare. Они не используются новой версией сайта.

## Ограничения

- GitHub Pages не является базой данных: каждое сохранение — commit в Git.
- Удалённые файлы остаются в истории Git; размер истории отдельно от размера текущего дерева.
- Для репозитория нет универсальной фиксированной квоты «свободного места». Не показывать выдуманный остаток.
- Состояние «прочитано» для новостей хранится локально в браузере/на устройстве и не синхронизируется между устройствами.
- Значок-колокольчик внутри сайта поддерживается. Официальная документация MAX Bridge на момент проверки не описывает API закрепления Mini App отдельным ярлыком Android или установки badge на иконку MAX; обещать это нельзя.
- Видеофайлы не загружаются в GitHub: хранится Rutube URL и метаданные. Воспроизведение в MAX и fullscreen нужно проверить на реальном устройстве.
